# Mission Control Event Schema

## Purpose

All observability sources should normalize into one event model so the UI and metrics reducers do not need to care whether a record came from desktop events, delegation, cron, kanban, or process tracking.

## Canonical shape

```json
{
  "event_id": "evt_01jmc...",
  "ts": "2026-07-31T11:30:00.000Z",
  "event_type": "profile.activity",
  "source_profile": "default",
  "target_profile": "coder",
  "session_id": "20260731_...",
  "run_id": "delegation_...",
  "task_id": "kanban_...",
  "status": "running",
  "model": "openai/gpt-5.4",
  "provider": "openai",
  "tokens_in": 1200,
  "tokens_out": 450,
  "estimated_cost_usd": 0.0231,
  "duration_ms": 12450,
  "metadata": {
    "title": "Implement issue triage panel",
    "raw_event_type": "delegate.completed"
  }
}
```

## Field notes

### Required

- `event_id`: unique identifier generated by the adapter/runtime
- `ts`: ISO timestamp when the event occurred or was observed
- `event_type`: normalized semantic type
- `status`: one of `observed`, `queued`, `running`, `completed`, `failed`, `blocked`, `idle`, `active`, `unknown`
- `metadata`: free-form diagnostics and source-specific details

### Optional but important

- `source_profile`: profile that emitted or initiated the event
- `target_profile`: profile handed work to, if any
- `session_id`: Hermes session identifier when known
- `run_id`: child-run / cron-run / background process / workflow identifier
- `task_id`: task/issue/kanban identifier when known
- `model`, `provider`: model execution metadata if exposed
- `tokens_in`, `tokens_out`, `estimated_cost_usd`: usage/cost fields when exposed or derived
- `duration_ms`: elapsed time for completed spans or rolling updates

## Suggested normalized event types

- `profile.activity`
- `profile.idle`
- `handoff.created`
- `handoff.accepted`
- `delegate.started`
- `delegate.completed`
- `delegate.failed`
- `cron.started`
- `cron.completed`
- `cron.failed`
- `kanban.claimed`
- `kanban.completed`
- `process.started`
- `process.completed`
- `usage.observed`
- `error.observed`

## Mapping guidance

- If the raw system is ambiguous, prefer a broader type over inventing precision.
- Keep raw source data inside `metadata`.
- Never drop the original source classification if available; store it as `metadata.raw_event_type`.
- If exact duration is not known, omit `duration_ms` rather than guessing.
- If cost is not known, omit `estimated_cost_usd` rather than synthesizing fake precision.
